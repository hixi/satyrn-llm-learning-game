# Satyrn 2.5D — Iteration 1: Mechanics + Basic World

Date: 2026-10-08. Status: proposed, pending owner sign-off.

Predecessor: the Phaser 2D "Satyrn — The Thread" (removed in `ab74042`).
This iteration keeps its spirit (small handmade worlds, one idea per world,
keepsakes, journal, no backend) but rebuilds as a **2.5D exploration game**
that explains how LLMs work. Future worlds (towers, libraries, …) each embody
one LLM concept; their content is deliberately NOT planned here.

## Locked decisions

| Decision | Choice | Rationale |
|---|---|---|
| Rendering | **Three.js**, real 3D scene, fixed angled follow camera (Diablo-style) | MIT licensed, first-class glTF support, small tree-shaken bundle, works on mobile browsers with light scenes |
| Alternative kept in mind | Babylon.js (Apache-2.0) if we later want built-in GUI/inspector at cost of bundle size | |
| World structure | **Walkable hub** with enterable buildings; interiors are separate scenes loaded on doorway trigger | proves the hub/interior pattern every future world will reuse |
| Asset pipeline | **glTF (.glb) models + textures** committed in `assets/`, low-poly, flat-shaded warm palette | owner preference; Draco/meshopt compression optional later |
| Controls | Desktop: WASD/arrows move, `E`/Enter interact, Q/R optional 90° camera snaps. Mobile: left virtual joystick, right interact button (shown when a target is near). One shared "intent" abstraction feeds the avatar. | owner requires both; no pathfinding on mobile — direct analog control |
| First-world concept | **Deferred.** Mechanics are generic enough that any concept world plugs into the `World` contract later. | owner said don't decide yet |
| Deployment | Same constraints as predecessor: static GitHub Pages, hash routing, `localStorage` saves, no backend, no accounts | Pages workflow already exists |

## Core loop (iteration 1)

Spawn in hub → walk around a small outdoor clearing → enter **First Chamber**
(a basic world building) → do a physical token/slot/trigger puzzle → receive a
keepsake + journal entry → exit back to hub. The loop is the skeleton every
future world hangs its LLM concept on.

## Mechanic primitives (the actual deliverable)

1. **Avatar + camera rig** — position-based movement on walkable ground,
   capsule-vs-obstacle collision, fixed-angle camera following with clamped
   zoom; snap-rotate option.
2. **Interact system** — proximity detection → floating prompt ("E" / tap
   button) → `Interactable` callbacks on world objects.
3. **Carriable tokens** — pick up / take back / place. One held at a time
   (capacity configurable per world); carriable objects are the universal
   teaching material of all worlds.
4. **Slots & containers** — pedestals/shelves that accept typed tokens and
   report state changes. (Future: capacity limits, fade rules, ordering — the
   context-window idea will be expressed here.)
5. **World state machine + triggers** — zones and conditions fire events
   (door opens, object spawns, light changes). Declarative, per-world logic
   file.
6. **Doors / scene transitions** — hub ↔ interior with fade; hash routes
   `#hub`, `#chamber`.
7. **Keepsakes + journal + HUD** — earning a keepsake writes a plain-language
   journal line; DOM overlay HUD; persisted in `localStorage`.
8. **Input layer** — keyboard and touch produce the same `move(x,y)` /
   `interact()` intents; touch controls appear on coarse pointers.

## Basic world: "The First Chamber"

Content-agnostic proving ground for primitives 2–5:

- A small room with 3 tokens (stone / lens / bell) and 3 pedestals.
- Reading the room (environmental labels, no lore yet): place the bell where
  the shelf-shadow is, stone in the dim corner, leave the lens in hand —
  placing the bell + stone opens the door and grants the **Wayfinder's Bell**
  keepsake.
- No LLM concept taught yet by design; the point is that the *mechanics feel
  right to build new worlds on*.

## Stack & structure

- Vite + TypeScript + three; DOM/CSS for HUD (no UI framework).
- `npm run dev` / `npm run build` / `npm run check` (tsc + tests); existing
  Pages workflow deploys `dist/` — assets ship as files alongside the bundle
  (single-file inlining is dropped since we now have .glb assets).

```
assets/            .glb models, textures (small, committed)
src/
  engine/          renderer bootstrap, camera rig, input (keys+touch), asset loader
  game/            state, scene manager, save/localStorage, keepsakes, journal
  worlds/          hub.ts, first-chamber.ts, contract.ts (World interface)
  ui/              HUD, interact prompt, touch controls, journal overlay
  main.ts          hash router bootstrap
```

## Mobile notes

- Cap `devicePixelRatio` at 2; low-poly budget (~5–15k tris per scene).
- WebGL2 required; graceful fallback message otherwise.
- Joystick via pointer events; interact button only when a target is in range.
- Portrait and landscape layouts; camera distance widens on small screens.

## Definition of done (iteration 1)

1. Hub renders with the Chamber building; enter/exit fade works; routes persist
   across reload.
2. First Chamber puzzle is solvable end-to-end using carry/slot/trigger/interact.
3. Playable with keyboard on desktop and with touch on a real phone.
4. At least one hand-authored .glb asset loaded through the pipeline.
5. Keepsake + journal entry persist in `localStorage` after reload.
6. `npm run check` green; Pages deploy from `main` works.

## Addendum — iteration 1.5 (same day)

- Camera reworked after owner feedback ("angle of the camera is a mess"):
  constant-offset steady camera in the hub — no zoom, no occlusion pull-ins —
  and fixed diorama cameras inside rooms with portrait auto-fit.
- Two content-agnostic sample worlds shipped to prove the loop end-to-end:
  **The Bell Foundry** (timing mini-game) and **The Lantern Library** (sorting
  mini-game), each entered through a hub door with its own exit and keepsake.
  LLM concept mapping stays deferred, per the locked decision.
- Carried tokens are not portable: the hand is cleared on every scene change.
- Smoke test grew to 40 checks covering all three worlds plus persistence.

### Iteration 2 — The Echo Hall (later same day)

- Built-in Web Audio synth (`src/engine/audio.ts`): two-oscillator plucked
  voice + generated reverb, no assets; starts on first user gesture and
  no-ops safely before that (the visual timeline runs on `performance.now`).
- `src/game/music/`: a small transition (Markov) model with 1–2 note context
  and temperature-scaled probabilities, plus three public-domain tunes that
  "pretrain" it on load. The model surface is ready for an MLP later.
- **The Echo Hall** world: the model drawn as a network of labelled nodes
  (notes, words, or both), live probability bars, and inference that continues
  a prompted song for eight notes. Cranks for temperature and memory; keepsake
  *the Echo*. Owner decision: ship a pretrained model first, retraining world
  later.
- Audio current state: synth only (owner choice); a sampled piano or MIDI-file
  import can sit behind the same `AudioKit`.

### Iteration 3 — two halls, many models (same day)

- Owner feedback: the Echo Hall was fun but its purpose, the training path and
  the consequences were unclear. Decision: cut the three sample worlds and
  build **two halls only** — a Training Hall and the Echo Hall.
- Removed `firstChamber`, `foundry`, `library` (worlds, hub buildings, routes,
  tests). The hub is now a two-door clearing (halls east and west).
- Added a **model registry** (`src/game/music/store.ts`): the preset "Old
  Songs" plus up to six models you train, named `Model 1…`, persisted in
  `localStorage`. The Echo Hall loads any of them ("load different models").
- Training Hall: DOM notebook (`src/ui/composer.ts`) with an eight-key piano
  and phrase strips; **Train** animates one `observe()` per note transition
  while the panel fills in; the notebook collapses during training so the
  network is visible. Drafts persist.
- Clarity pass: status board (`Model: X · N transitions`), purpose caption,
  control labels, model-loaded toasts, and input suppression behind the
  notebook so world interaction can't fire accidentally.
- Fixed: spawn-overlap immobility (collision now allows escaping an overlap;
  echo spawn no longer sits inside a stand) and scenery hiding the character
  (`OccluderFader` ghosts meshes between camera and character, plus an x-ray
  silhouette). Verified by new walkability and occlusion smoke checks.

### Iteration 4 — prompts are user input; guided training (same day)

- Owner feedback: the Echo Hall's "prompt" was a training sample to pick, but a
  prompt should be the player's own input; and training was unintuitive without
  prior knowledge. Fixes: the Echo Hall's ask keys (`src/ui/asker.ts`) let the
  player play a 1–4 note prompt with a live "expects …" readout, Sample borrows
  the model's opening, and Continue generates from the played prompt. The
  Training Hall gains explicit steps (1 compose · 2 train · 3 hear it next
  door), a panel explainer sign, and caps/steps in the captions.
- Verdict on running a real LLM in-browser: deferred. WebLLM/Transformers.js
  require hundreds of MB–GB of downloaded weights and WebGPU, contradicting the
  offline/static promise, and a text LLM breaks the music metaphor. The honest
  "real model" upgrade is a small MLP trained live with backprop behind the
  same `MusicModel` surface; a real LLM would be an explicit opt-in mode at most.

### Iteration 5 — help desks, scrollable (same day)

- Owner feedback: the explanations were too terse; add scrollable texts as a
  help desk in each hall. `src/game/help.ts` holds the copy (steps, what the
  model is, how to read the panel, what heat/memory do, try-this prompts);
  `src/ui/help.ts` renders a scrollable paper sheet opened by an in-world
  lectern in each hall. Panels get `touch-action: pan-y` so they scroll by
  touch (the body disables touch gestures).
- Fixed a real bug this surfaced: world-owned DOM UIs (composer, asker, help)
  were never removed on unload, so duplicate element ids accumulated across
  visits. They now expose `dispose()` and the worlds call it.
- Interact prompts are hidden while any panel owns input (`setSuppressed`), so
  the UI never advertises an action that is currently disabled.

### Iteration 6 — the real model (same day)

- Owner asked for a real model; built a genuine in-browser neural network
  rather than a downloaded LLM (which would break the offline/static promise).
  `src/game/music/mlp.ts`: context one-hot (2 notes) → 8 hidden tanh → softmax,
  cross-entropy loss, SGD, seeded init, serialisable weights.
- Both kinds share the `MusicModel` surface, so the halls treat them alike;
  the registry stores `kind` and the trained weights.
- `NetPanel` gained a middle column ("how it mixes") shown for networks, with
  edges coloured by weight sign and sized by magnitude, plus live hidden-layer
  activations. The Training Hall adds a **Method** stand (counter/network) and
  a network run with a falling loss; near-zero loss on one phrase is called out
  as overfitting. The Echo Hall loads either kind and its Memory crank blanks
  the older input slot for networks.
- Verdict stands: a browser LLM (WebLLM/transformers.js) remains out of scope
  for weight-download and WebGPU reasons; this network is the honest "real".
- Follow-up: the built-in Old Songs now ships as *both* kinds — a counter preset
  and a trained-network preset (deterministic rebuild, memoised) — so the same
  corpus can be heard through both machines.

## Explicitly out of scope

- Audio, gamepad, click-to-move/pathfinding, NPC dialogue, art polish.
